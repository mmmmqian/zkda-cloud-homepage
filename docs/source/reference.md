### 可借鉴的结构原则

#### 1. 先定位，再证明，后展开

- 首屏先给出清晰的品牌定位与主动作。
- 紧接公开数据或可信事实，让价值主张有证据承接。
- 再展开平台架构、三大产品、迁移方案、生态与专家服务，形成有章节感的长页面，而不是平均铺满同尺寸卡片。
- 每一项重要主张附近放置与它直接相关的数据、能力或说明，避免把所有证据集中到孤立的“客户墙”。

#### 2. 首页负责总览，详情页负责密度

- 首页解释中科达云的整体关系和关键入口，不把技术功能清单全部堆在一个页面。
- 产品、解决方案和专家服务页分别承载更完整的场景、能力、流程和技术细节。
- 产品文档、API 文档和帮助中心保持独立的信息架构；价格或大规模参数表也不进入首页营销叙事。

#### 3. 用章节推进产品故事

- 首页沿用已经确认的 15 段内容顺序，但通过“定位—证据—平台—产品—迁移—生态—服务—行动”的大章节组织节奏。
- 产品总览先说明三者关系，再分别引向智算云平台、Token Hub 和 AutoDev。
- 迁移内容以过程和结果推进，后续动态只帮助理解，不承担内容是否可见。

### 导航行为建议

以下方案把 Together AI 录屏中已观察到的互动原则与中科达云既有导航层级结合。触发、切换与移动分组来自 Observed 证据；键盘、无 JavaScript 和减少动画行为是本站为可访问性补充的设计决定。

#### 电脑端

- 顶部导航保持固定；产品、解决方案、专家服务、资源悬停即开，并在横向移动时直接切换当前浮层。
- 浮层使用“条目名称 + 简短说明 + 辅助导览”两区结构，但不复制 Together AI 的图标、图片、文案、颜色或具体构图。
- 指针离开导航、点击导航外部或按 `Escape` 关闭下拉；点击与键盘仍可操作，焦点始终可见。
- 登录与免费体验持续位于导航右侧，不被下拉内容遮蔽。

#### 手机端

- 一个“菜单”按钮打开覆盖剩余视口的纵向菜单；分类使用单组展开的原生手风琴。
- 展开内容在分类下方原位出现，不引入多层返回页面；登录与免费体验保持可见。
- 关闭按钮与 `Escape` 均可收起菜单。
- JavaScript 关闭时主导航直接显示，各分组仍可使用原生控件展开，保证所有核心入口可读取。

### 明确拒绝的模式与复制边界

- 不复制参考网站的图片、视频、图标、代码、文案、完整构图或品牌比例。
- 不使用 Transform9 的医疗场景、客户 Logo、推荐语、表单或效果数据作为中科达云证据。
- `tr9.webflow.io` 首屏后的连续 Logo 带只用于确认“全宽单行循环”的结构机制；不复制其中的客户 Logo、排序、速度、深色背景、代码或完整构图。
- 不制作没有来源的客户墙、案例、评价、认证标志或业务数据。
- 不使用大面积渐变光球、模糊发光、占位插画和反复出现的三列卡片网格来代替信息设计。
- 不照搬英文网站的字号比例、行长和断行；中文排版必须单独验证。
- 不把未在真实浏览器中验证的菜单、悬停、移动端或滚动行为描述为参考网站事实。
- 不让动效隐藏核心内容；减少动画、手机、无 JavaScript 或动画依赖失败时都保留完整静态叙事。
