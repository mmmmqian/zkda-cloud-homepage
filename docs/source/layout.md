## Decisions

### 全站排版原则

- 使用当前 16 页真实中文内容，不用占位文字替代真实长度；关于我们采用用户新提供的长内容重新排版。
- 页面背景可以全宽延伸，但每个 Section 都有自己的内容宽度；不使用一个页面级容器包住所有 Section。
- 设四类内容宽度：`reading` 约 760–820px 用于说明文字，`md` 约 1120px 用于判断与边界内容，`xl` 约 1280–1320px 用于常规页面主体，`full` 约 1400–1440px 用于数据、流程和宽列表。全部保留 `20–72px` 流动边距。
- 大标题、段落、列表、数字条、流程、联系信息和占位媒体使用开放式排版与分隔线，不新增圆角卡片、嵌套卡片、Bento 或装饰性 3×2 卡片矩阵。
- 电脑端用宽度变化、左右错位、单排步骤和开放列表形成节奏；手机端全部回到单列阅读顺序，按钮变为整行，横向流程改为纵向。
- 每页最多保留一个明显的结束行动区；页首按钮、内容内文字链接和页脚不计为重复结束行动区。

### F01｜全站顶部与页脚

- 顶部顺序保持：首页 → 产品 → 解决方案 → 专家服务 → 定价 → 资源 → 关于我们 → 登录 / 免费体验。
- 电脑端顶部三段式分配：品牌 Logo、居中导航、账户动作；下拉菜单仍使用已批准的悬停打开与横向切换方式。
- 900px 及以下显示菜单按钮；展开后使用整屏菜单与原生分组控件。页面正文不因菜单打开而横向移动。
- 首页页脚按最新版内容框架改为 27% 品牌说明 + 73% 目录区，目录包含产品、解决方案、专家服务、资源、公司与联系六组真实入口，版权信息横跨全宽；620px 以下改为单列并以两列目录排列，邮件与电话保持可直接点击。内页页脚继续使用原有共享外壳。

### F02｜首页

- `#top`：2026-09-08 以 Figma 节点 `64:34956` 作为首页 Hero 静态视觉 Source of Truth。桌面参考画板 `1651×863`：标题左锚点约 `36px`、顶部约 `78px`，标题 `100px / 122px` 常规字重，品牌蓝仅用于“全面 智能”；下方约 `356px` 的 `50 / 50` 双栏分别呈现“我们是谁：”与“联系我们：”，右栏使用 `contact@zhongkedayun.com`。Hero 在 `≥992px` 使用同一套 Figma-derived 连续缩放，不再由 `100svh` 主导；`768–991px` Tablet 保持 Lower Grid `50 / 50` 双栏构图语法，只压缩字号与间距；`480–767px` 因长正文与长邮箱进入 Selective Reflow，`≤479px` Mobile Portrait 可完整 Recompose。Lower Grid 顶部分割线是 Stage-level full-bleed divider，所有宽度都必须从 viewport 左边缘贯穿至右边缘；`≥768px` 保留中央竖线，`<768px` 堆叠后改为内容块间横线。动态背景不承担文字信息。
- 首屏之后新增连续品牌带：背景沿用首屏暖白浅色，按用户最新截图反馈移除“国产芯片生态 / 连接多元国产算力 / 素材说明”整块标题区，公开页面只保留暂停控制与全宽单行 Logo 轨道；不把该列表包装为客户墙或合作伙伴证明。
- 2026-08-28 以 Figma 主画板节点 `64:34873` 再次校准首页纵向节奏：卡商 Logo 循环带在 `1651px` 桌面基准下高 `165px`，Logo 继续保持 `35px` 等高和原始宽高比，并由轨道明确垂直居中；`#proof` 结束到 `#products` 起点保留 `260px` 空白，`#capabilities` 在自身标题带之前同样保留 `260px` 空白。三处尺寸在窄屏按同一流动规则收敛，手机最低分别为 `120px` Logo 带和 `96px` 区块留白。
- 12 个品牌使用用户提供的 6 个 SVG 与 6 个透明 PNG，统一放入等高、等宽的透明容器并使用 `object-fit: contain` 保留各自比例，不裁切、不重绘、不强制单色化。
- 手机端缩小 Logo 容器与间距，保持单行循环；循环带提供鼠标悬停暂停和键盘 / 触屏可操作的暂停开关；减少动画时停止自动循环，并允许用户横向浏览完整列表。
- `#proof`：四组公开数据在电脑端单排、平板 2×2、手机单列；使用线条分隔而不是卡片。
- `#products`：合并原 `#stack` 与产品总览的内容边界保持不变；2026-08-26 用户在视觉阶段以 Figma 节点明确修订呈现方式，改为单个浅色全宽产品轮播。桌面由超大标题、约 30% 左侧产品 GIF、右侧关系说明 / 详情链接 / 能力标签组成；箭头依次切换智算云平台、Token Hub、AutoDev。`01 / 03` 位于右侧内容栏左上角，正文在其下方居中展开。721–900px 继续保持两栏，双箭头由 100px 连续缩到 76px。720px 以下使用标题—控制带—插图—说明—两列能力的纵向顺序；序号位于 62px 控制带左侧，双箭头位于右侧，GIF 使用原始 3:4 比例满宽显示，不让序号覆盖图片。首页仍只解释三者位置与承接关系，具体功能进入详情页。主画板中数据区结束于 `y=1715.921875`、产品区起于 `y=1976`，因此产品区上方留白按 `260px` 实现。
- `#capabilities`：以 Figma 节点 `60:34731` 使用浅色全宽双栏，并按用户补充加入第六张 AutoDev 卡。桌面左侧为固定的“覆盖 AI 全生命周期”总结与三项基础保障；右侧六张蓝到近黑的能力卡使用相同的展开高度。未来卡片先停在屏幕下方，随后逐张上移覆盖前一张，只让已浏览卡片露出等高标题条。整体堆叠高度随 01→06 逐步增加，当前卡下方保留浅色留白；直到 06 出现，五条历史标题加当前卡才刚好填满固定区域。`721–1023px` 取消桌面 pin/absolute stack，使用可读的普通文档流；`720px` 以下先显示总结，再把六张默认完整展开的卡片纵向排列；滚动时后一卡以 sticky 方式逐张覆盖前一卡正文，并留下约 74px 的历史标题条形成顶部堆叠。六张卡通过补偿外边距共享同一父容器释放边界：06 到达五条历史标题后的固定卡位便停止单独移动，继续滚动时完整六层堆叠由下一章节整体推离。新版主画板节点 `64:35470` 明确使用 `padding-top: 260px`，该空白位于平台能力标题带之前，不参与卡片堆叠高度计算。
- 锁定范围：`#top` 首屏、卡商 Logo 循环、`#proof`、`#products`、`#capabilities` 为已确认区，本轮不改其文案、数据、链接、素材或结构。
- `#advantages`：使用全宽 27 / 73 结构；右侧先以两项更大 Spotlight 呈现一云多芯与平滑迁移，再用 2×2 支撑技术降本、安全可控、智能运维、行业知识；620px 以下全部改为单列。

- `#ecosystem`：深色全宽内容区承接芯片—框架—模型—应用关系，并单独强调中科达云是开放、中立的基础设施连接层；不复制平台能力区的滚动结构。
- `#about`：使用四列关键词呈现 Expertise / Technology / Industry / Innovation，手机改为 2×2；`#final` 只保留免费体验与联系我们两个行动。
- 删除重复或不在 v1.1 最终叙事中的首页独立区：`#multi-chip`、`#migration`、`#trust`、`#services`。相关产品、迁移、事实边界与服务入口仍由核心优势、专业服务、详情页和页脚承接。

### F03｜产品详情（3 页）

- 路由：智算云平台、Token Hub、AutoDev。
- 当前为用户指定的临时单屏版本：只保留全站导航与各产品第一屏 `content-hero`，首屏中的面包屑、产品定位、标题、简介和行动按钮保持不变。
- `#audience`、`#relation`、`#capabilities`、`#path`、`#related` 以及页脚暂时不渲染；它们的已确认文字仍保存在内容源中，后续可按指令恢复，不视为永久删除产品信息架构。
- 本次收缩只作用于三个产品详情页，不改变首页产品体系轮播、其他内页或全站导航。

### F04｜解决方案详情（4 页）

- 临时覆盖规则：F04–F08 当前对应的 12 个页面统一使用同一缺省页构图——全站导航、单个浅色首屏、状态提示、标题、短说明与返回首页按钮；原正文模块及内页页脚暂时隐藏，不进入当前视觉检查。
- 首屏与产品页共用文字宽度，但问题背景和实施路径使用不同横向密度。
- 国产算力迁移的素材缺口继续显示明确占位图：电脑 16:9、手机 4:5，保留几何空间且不伪装正式图片。
- `#context`：3 个问题点在电脑端单排，先让访客看清为什么需要方案。
- `#stage` 与 `#boundary`：缩窄到约 1120px，避免范围说明被摊得过宽。
- `#flow`：约 1400px 的四步单排流程；每步用编号、标题和短说明形成连续路径。900px 以下回到单列。
- `#related`：全宽背景内使用两条相邻产品 / 服务入口，不增加案例或量化承诺。

### F05｜专家服务详情（3 页）

- `#stage`：3 个适用条件在电脑端单排，先帮助访客判断是否需要专项协作。
- `#scope`：使用向右缩进的纵向开放列表，强调输入、协作、输出边界；不和上一段重复三列构图。
- `#flow`：4 个真实步骤电脑端单排，手机端纵向；`#prepare` 保留纵向清单，形成快慢节奏。
- `#related`：只连接关于我们页内联系区和相关平台 / 方案，不把专家服务包装为固定套餐。

### F06｜定价页

- 首屏保留大标题、事实边界和“咨询方案 / 免费体验”两个不同优先级动作。
- `#factors`：3 个方案构成电脑端单排；`#prepare` 改回纵向清单，避免连续同构。
- `#boundary`：缩窄到约 1120px，以较长行距呈现币种、税费、计价单位、数量和有效期均待确认的事实。
- `#related`：页面唯一明显结束行动区，连接关于我们页内联系区与首页；不显示虚构金额、套餐或价格卡片。

### F07｜资源工具页（3 页）

- 页面整体比产品 / 方案页更紧凑，优先说明“当前已有 / 尚未提供 / 现在可以做什么”。
- `#status`：3 项状态电脑端单排；`#topics` 使用向右缩进的纵向目录，避免像营销卡片。
- `#help`：缩窄到约 1120px，说明找不到内容时的真实联系路径。
- `#related`：连接关于我们页内联系区与同组资源页。外部文档系统地址未提供前，本地说明页保持可阅读但不伪装完整文档站。

### F08｜关于我们

- 首屏用使命形成页面主叙事，按钮分别连接免费体验和本页邮件区域。
- `#principles`：使命与愿景电脑端左右并列，价值观四项单排；900px 以下使命 / 愿景改为上下排列，价值观改为 2×2。
- `#timeline`：五个发展节点使用开放式纵向时间轴，年份与事件左右分栏；手机端年份置于事件上方。
- `#team`：四位团队成员电脑端单排，以分隔线建立层级，不使用人物卡片或虚构照片；900px 以下逐人纵排。
- `#contact`：合并原独立联系页，邮件使用整行快捷入口，电话与地址作为后续信息行；手机端所有信息纵排并允许长邮箱换行。
