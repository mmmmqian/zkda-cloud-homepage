## Decisions

### 文字写法比较

四个方案保持事实与信息量大致一致，只改变读起来的感觉。真实网站采用用户已通过 `next:layout` 批准的推荐方案 A。B01 已完成生成；用户随后明确取消首页图片并要求国产算力迁移页面暂不使用生成图，两个生成候选都只保留为内部记录。迁移页面继续显示诚实占位图。用户又通过 `revise:sitemap-pricing` 批准新增“定价”；2026-08-24 再要求取消独立联系页并把联系入口并入关于我们，当前公开页面为 16 页。

#### A｜平台判断型（推荐，当前已填入网站）

- 感觉：克制、直接、兼顾企业决策和技术判断。
- 信息密度：中等；先解释平台关系与企业价值，再给必要技术范围。
- 术语处理：保留“一云多芯、Token Hub、MaaS”等必要词，第一次出现时用普通中文解释。
- 适合原因：中科达云既需要建立基础设施品牌，也要让技术负责人判断产品是否与当前场景有关。
- 风险：如果后续没有真实产品截图与案例，内容可能显得理性但证据不足；必须继续保持公开边界。
- 同一事实示例：
  - 首页标题：**把国产算力、模型服务与 AI 应用开发，连接成一套基础设施**
  - 介绍：中科达云以智算云平台为底座，通过 Token Hub 连接模型服务，再由 AutoDev 支撑 AI 应用开发，帮助企业降低异构算力管理与国产化迁移复杂度。
  - 主按钮：**免费体验**

#### B｜工程说明型

- 感觉：技术密度更高，像一份精炼的解决方案说明。
- 信息密度：较高；更早出现资源池、训练、推理、模型服务与运维等词。
- 术语处理：适合技术负责人，但企业决策者需要更多阅读成本。
- 适合原因：能快速建立工程可信度。
- 风险：首页容易接近产品手册，品牌记忆点变弱。
- 同一事实示例：
  - 首页标题：**统一纳管异构算力，贯通训练、推理与模型服务**
  - 介绍：中科达云以多芯资源管理为底座，连接模型 API 与 AI 应用开发流程，为企业提供从计算到应用的连续基础设施。
  - 主按钮：**查看平台能力**

#### C｜品牌宣言型

- 感觉：短、强、具有传播性。
- 信息密度：较低；依靠后续区块补足产品关系。
- 术语处理：首屏尽量不使用复杂词。
- 适合原因：有利于建立国产 AI 基础设施品牌记忆。
- 风险：如果表达过度，会接近空泛的“领先科技”宣传。
- 同一事实示例：
  - 首页标题：**让国产算力真正进入企业 AI 生产环境**
  - 介绍：从算力、模型到应用，中科达云把分散的技术环节连接为一套可持续运行的基础设施。
  - 主按钮：**开始体验**

#### D｜共建顾问型

- 感觉：更温和，强调与企业团队共同推进。
- 信息密度：中等偏低；优先说明企业当前阶段与下一步。
- 术语处理：用问题和场景解释技术能力。
- 适合原因：适合解决方案与专家服务页面。
- 风险：会削弱平台产品的独立品牌感，也可能让官网看起来更像咨询公司。
- 同一事实示例：
  - 首页标题：**从第一张国产 GPU 到企业 AI 应用，我们与你一起搭建**
  - 介绍：无论你正在迁移工作负载、建设智算中心还是开发 AI 应用，中科达云都从现有环境出发连接算力、模型与开发流程。

### 2026-08-21｜Transform9+ 首屏背景动效补充观察与实现决定

- 用户明确要求：首页第一屏完全参考 [Transform9+](https://www.transform9.com/) 的背景动效机制作为主视觉，不使用图片。
- 访问情况：自动观察接口多次连接超时，但公开网页内容读取成功；随后在用户电脑现有 Chrome 中正常打开并观察首屏。内部证据保存在 `docs/evidence/transform9-hero-motion-20260821/`。
- 已观察：首屏为覆盖整个黑色区域的动态像素场；大块低分辨率矩形缓慢漂移并进行明暗呼吸；蓝色和绿色只出现在少数单元；鼠标附近出现柔和荧光绿光晕并增强周边色块；标题、细分隔线与操作区位于动态图层上方。
- 用户进一步指出色块前方存在类似高斯模糊的柔化层，并反馈首版自主实现效果不佳；随后明确底层仍是整齐排列的正方形色块，鼠标聚焦位置的色块会闪烁。最终版因此采用规则正方形矩阵、低亮远端呼吸、鼠标邻近格快速明暗闪烁与独立前景柔焦叠层，清晰文字和网格仍位于最上方。
- 用户提出因仅作学习 Demo 可直接复制对方代码；但“学习用途”本身不构成源码或第三方场景的使用授权。除非用户提供权利方明确许可的源码或官方嵌入代码，本站继续只复现公开可见的互动机制，不提取或复制私有代码、场景 ID 与素材。
- 未观察 / 不推断：对方源码、具体噪声算法、精确帧率、数值参数、手机端内部实现和第三方场景配置。
- 用户最终指定首屏技术分层：底层 `WebGL Canvas` 负责 gradient field、noise 与 light deformation；中层 `Data Grid` 使用独立 Canvas 绘制规则正方形和随机激活格；上层 DOM 保留导航、标题和按钮，并以 GSAP 入场。
- 本站实现：使用原生 WebGL 片元着色器生成低亮蓝绿渐变场、连续噪声与轻微形变；独立 Canvas 2D 绘制规则正方形数据矩阵。远端格子低亮缓慢呼吸，鼠标只轻微提高邻近格的事件概率和可见度，不改变格子色相；鼠标本身不绘制圆形光晕。前景 CSS 柔焦层融合边缘，标题、按钮、导航与细网格保持真实 DOM / 清晰图层。
